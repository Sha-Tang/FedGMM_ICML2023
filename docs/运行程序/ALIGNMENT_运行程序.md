# FedGMM项目运行任务对齐文档

## 1. 项目上下文分析

### 项目基本信息
- **项目名称**: FedGMM - Personalized Federated Learning under Mixture of Distributions
- **项目类型**: 联邦学习研究框架
- **技术领域**: 个性化联邦学习、高斯混合模型、分布式机器学习
- **发表来源**: ICML 2023

### 技术栈分析
- **核心框架**: PyTorch 2.6.0 + TorchVision 0.21.0
- **科学计算**: NumPy 2.2.3, SciPy 1.15.2, scikit-learn 1.5.0
- **可视化**: matplotlib 3.10.0, TensorBoard 2.19.0
- **其他依赖**: tqdm, Pillow, cvxpy等
- **运行环境**: 支持CPU/CUDA

### 支持的算法和数据集
**联邦学习算法**:
- FedGMM (核心算法)
- FedAvg, FedProx, FedEM
- pFedMe, AFL, FFL
- Clustered FL, L2SGD, APFL

**数据集支持**:
- 图像分类: CIFAR10/100 (MobileNet-v2)
- 手写识别: EMNIST/FEMNIST (2-layer CNN + FFN)  
- 语言建模: Shakespeare (LSTM)
- 合成数据集: Synthetic (Linear Model)

### 代码模式和约定
- **模块化设计**: 清晰的客户端-服务端分离
- **可扩展架构**: 通过继承实现不同算法
- **配置驱动**: utils/constants.py统一配置
- **实验管理**: TensorBoard日志 + 模型保存
- **数据预处理**: PCA降维 + 数据分割

## 3. 需求理解确认

### 当前理解
用户希望运行FedGMM联邦学习实验，但具体需求存在以下不确定性：

### 边界确认
**明确的边界**:
- 基于现有FedGMM代码框架
- 遵循6A工作流程规范
- 使用项目已支持的数据集和算法

**需要确认的边界**:
1. **实验目标**: 是运行完整训练还是快速验证？
2. **数据集选择**: 使用哪个数据集(CIFAR10/EMNIST/Shakespeare等)？
3. **算法选择**: 使用FedGMM还是对比多种算法？
4. **计算资源**: CPU还是GPU训练？本地还是分布式？
5. **实验规模**: 客户端数量、训练轮数、批次大小等参数？

### 疑问澄清

#### 1. 数据集准备状态
- 当前data/目录下各数据集是否已准备就绪？
- 是否需要下载和预处理数据？

#### 2. 实验配置偏好
- 轻量级验证实验 vs 完整性能测试？
- 单一算法测试 vs 多算法对比？

#### 3. 环境和资源
- 硬件配置：CPU/GPU偏好？
- 训练时长期望：快速验证(分钟级) vs 完整训练(小时级)？

#### 4. 输出要求
- 是否需要生成可视化结果？
- 是否需要性能对比报告？

## 4. 基于项目知识的推理决策

### 推荐配置(基于README示例)
```bash
# 标准CIFAR10 FedGMM实验
python run_experiment.py cifar10 FedGMM \
    --n_learners 3 \
    --n_gmm 3 \
    --n_rounds 200 \
    --bz 128 \
    --lr 0.01 \
    --lr_scheduler multi_step \
    --log_freq 5 \
    --device cpu \
    --optimizer sgd \
    --seed 1234 \
    --logs_dir ./logs \
    --verbose 1
```

### 快速验证配置
```bash
# 轻量级验证实验(减少轮数)
python run_experiment.py cifar10 FedGMM \
    --n_learners 3 \
```
