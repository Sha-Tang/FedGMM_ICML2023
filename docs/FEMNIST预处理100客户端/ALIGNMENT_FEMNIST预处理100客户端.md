# FEMNIST数据预处理100客户端任务对齐文档

## 1. 项目上下文分析

### 项目基本信息
- **项目名称**: FedGMM - Personalized Federated Learning under Mixture of Distributions
- **项目类型**: 联邦学习研究框架 (ICML 2023)
- **核心技术**: 高斯混合模型的个性化联邦学习
- **当前状态**: 已有FEMNIST数据处理框架，需要扩展到100个客户端

### 技术栈分析
- **核心框架**: PyTorch 2.6.0 + TorchVision 0.21.0
- **数据处理**: NumPy, scikit-learn, PIL
- **联邦学习**: 自定义Aggregator和Client架构
- **数据格式**: .pt文件存储tensor数据，.pkl文件存储索引

### 项目架构理解
```
现有FEMNIST数据处理流程:
原始LEAF数据 → preprocess.sh → data_as_tensor_by_writer → generate_data.py → 联邦客户端数据分片
```

**核心组件**:
- `data/femnist/generate_data.py`: 主数据生成脚本
- `data/femnist/intermediate/data_as_tensor_by_writer/`: 按作者分组的原始数据
- `datasets.py`: SubFEMNIST数据集类定义
- `utils/utils.py`: 数据加载器工具函数

### 现有数据处理机制分析
1. **数据源**: LEAF预处理的Extended MNIST，按作者(writer)分组
2. **数据变换**: 包含随机旋转、翻转、标签投影等增强
3. **分割方式**: 基于作者自然分布，支持train/test/val分割
4. **存储格式**: 每个客户端一个文件夹，包含train.pt和test.pt

## 3. 疑问澄清(存在歧义的地方)

### 关键决策点需要确认

#### Q1: 数据分布策略
**问题**: 100个客户端的数据应该如何分布？
**选项**:
- A. 均匀分布：每个客户端样本数量相近
- B. 自然分布：保持原始作者数据的不平衡性
- C. 混合策略：部分均匀，部分保持自然分布

**建议**: 选择B(自然分布)，因为这更符合联邦学习的真实场景，也是FEMNIST数据集的设计初衷。

#### Q2: 数据量控制
**问题**: 如何确保100个客户端都有足够的训练数据？
**分析**: 
- 当前intermediate/data_as_tensor_by_writer包含约3500个作者文件
- 使用s_frac=0.03可以获得约105个客户端
- 需要验证每个客户端的最小样本数量

**建议**: 设置s_frac=0.03，并添加最小样本数量检查机制。

#### Q3: 验证集策略
**问题**: 是否需要为每个客户端生成验证集？
**分析**: 现有代码支持val_frac参数，可以从训练集中分割验证集

**建议**: 设置val_frac=0.1，为每个客户端生成10%的验证集，用于本地模型调优。
